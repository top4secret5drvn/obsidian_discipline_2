# Дорожные карты LifeTracker

Открытие: иконка карты на боковой панели, команда **LT: дорожные карты** или кнопка на дашборде. Версия плагина: 0.4.0.

## Использование

1. Создайте карту, задайте название, описание, иконку, цвет и необязательный срок.
2. Добавьте уровни. В каждом добавьте условия или вложенные группы AND/OR. Стрелки меняют порядок уровней и условий. Выбирайте сущности по названиям, а не ID.
3. Сохраните и нажмите **Запустить дорожную карту**. Только первый уровень начнёт учитывать прогресс. Будущие уровни можно раскрывать.
4. Когда логическая структура выполнена, нажмите **Завершить уровень**. Проверка повторяется по свежим данным перед записью; следующий уровень активируется в той же транзакции.
5. Запущенную карту можно архивировать, удалить или дублировать. Её оформление редактируется, но уровни и условия защищены от изменения истории. Копия получает новые ID и начинает без прогресса.

Пример трёх уровней: (1) выполнения выбранной привычки; (2) AND доходы выбранной категории после активации + абсолютная ступень навыка; (3) AND завершение выбранного дела после активации + наличие достижения. Проверки автоматические, переход — с ручным подтверждением.

## Реальные источники

| Категория | Метрики |
| --- | --- |
| Привычки | Отметки выполнения, часы, дневной процент выполнения |
| Активности | Записанный объём, расчётные потраченные калории |
| Навыки | Часы с весами связей привычек, существующие ступени 0–7 |
| Финансы | Доходы, расходы, баланс доходов и расходов; фильтр категории |
| Дела и идеи | Завершённые элементы; текущие статусы backlog, in_progress, done, dropped; идеи и дела разделены |
| Цели | Завершения и реальные статусы active, achieved, completed |
| Питание | Калории, дни в заданном диапазоне калорий, отмеченные калориями приёмы пищи с фильтром слота |
| Вещества | Дни с отметкой приёма, текущий/максимальный стрик; только конкретное вещество |
| Игра | XP, уровень персонажа, XP дневных действий, характеристики, очки славы, слоты, достижения, трофеи |
| Состояние | Оценки фокуса, внимания, трения, скорости мышления, энергии и настроения |
| Курсы | Изученные части, выполненные повторения, процент прогресса курса |

Сумма, количество событий, уникальные дни, текущий и максимальный стрики, среднее, текущие значения, прирост и наличие события доступны там, где это соответствует типу метрики. Текущие статусы проверяются как количество совпадений: для конкретного объекта `≥ 1`. Несколько конкретных объектов требуют отдельных условий в AND-группе.

Ступени навыка: 0 Новичок, 1 Начинающий, 2 Практик, 3 Опытный, 4 Профессионал, 5 Эксперт, 6 Мастер, 7 Легенда. Отдельного XP навыка нет. Финансовый баланс — разница записанных доходов/расходов, не банковский остаток. Единицы объёма активности задаются её существующим смыслом (шаги, минуты и т. п.); автоматической конвертации нет.

## Время и расчёты

- `since_activation`: события до дня активации исключены; для дня активации вычитается зафиксированное начальное значение. Если до открытия уровня уже записано 1000 ₽, добавление ещё 5000 ₽ в этот же день даёт ровно 5000 ₽ прогресса.
- `absolute`: текущий показатель или агрегат за выбранный период всей истории. Например, ступень навыка или наличие достижения. Скалярный прирост использует начальное значение и режим `since_activation`.
- Журнал имеет дневную точность: время отдельных транзакций и отметок не хранится. Базовые значения сохраняются для дня старта, а не как копия всей истории. Правка старой суммы в день активации считается изменением этой суммы; отличить исправление от нового действия без новых временных данных невозможно. Задним числом внесённые события до даты активации не засчитываются.
- Данные с будущими датами не засчитываются до наступления этих дат. Явный период пересекается с периодом уровня.
- Стрик разрывается пропущенным календарным днём. Текущий стрик должен заканчиваться сегодня (либо на уже прошедшем конце явного периода), максимальный сохраняет наибольшую последовательность внутри периода. День активации с уже выполненной привычкой повторно не засчитывается.
- Среднее считается по записанным дням после суммирования выбранных событий внутри каждого дня; отсутствующие дни не превращаются в нули. Пустая выборка среднего — отсутствие данных, не ноль.
- Событие активности — дневная запись активности, а не отдельное повторение. Для количества повторений используйте сумму объёма. Событие выполнения задачи учитывается по её стабильному ID, даже если оно одновременно есть в workItems и журнале.
- Для событийных условий `≤`, `<` и диапазона обязателен конец периода. Они могут стать выполненными только после его окончания. Для них нет вводящей в заблуждение процентной шкалы. Готовность всех условий всегда определяется сравнением, а не процентом.
- Достигнутые уровни фиксируют условия, значения и названия объектов на момент подтверждения. Позднейшие правки, переименования, удаления и прерывания стриков не откатывают завершение.
- Удалённый выбранный источник даёт статус «недоступен», а не числовой ноль. Ошибка чтения/JSON прерывает проверку и не открывает следующий уровень.
- Дорожные карты не запрещают другие действия пользователя. Существующее правило обязательных привычек остаётся самостоятельным.

## Хранение и обновления

`LifeTracker/roadmaps.json`, schemaVersion 1: карты, уровни, дерево условий, даты активации/завершения, базовые значения и снимки результатов завершения. Журналы и справочники читаются из существующих файлов и не изменяются движком.

Проверки выводятся из актуальных источников: locked → active → ready; completed хранится как неизменяемый снимок. После перезапуска ready восстанавливается пересчётом. Сохранения дневника, справочников, дел, наград и курсов уведомляют открытый раздел. Внешние изменения отслеживаются событиями Vault; раз в минуту открытый экран перечитывает источники, в том числе после смены дня. Кнопка обновления доступна постоянно.

Экспорт остаётся из четырёх файлов: дорожные карты включены в `goals-ideas-tasks-skills-rewards.json` в поле `roadmaps`. Существующего импорта в проекте нет; новый импорт не добавлен. Общий процент карты — завершённые уровни плюс доля активного, будущие уровни не накапливают прогресс.

## Расширение реестра

`roadmaps.js` содержит независимые адаптеры и общий движок, `MetricRegistry.register()` добавляет показатель без изменения механизма уровней. Получить реестр в плагине можно через `store.roadmaps.registry`.

```js
store.roadmaps.registry.register({
  key: 'extension.score', label: 'Рейтинг', source: 'Расширение',
  kind: 'scalar', unit: 'очки',
  read: ctx => ({ available: true, value: readExistingScore(ctx) })
});
```

Числовой текущий источник возвращает `{available, value}`; событийный — `{available, events: [{id, date: 'YYYY-MM-DD', value}]}`. События требуют стабильных уникальных ID, не индексов массива. Для дневных журналов используйте агрегаты `date:entityId`; их значения можно корректно вычесть при старте посреди дня. Опциональные поля адаптера: `entities(ctx)`, `collection`, `requireEntity`, `methods`, `statuses`, `signed`. Расширение должно повторно регистрировать адаптер при старте приложения; неизвестная метрика остаётся недоступной. Движок не создаёт вымышленных источников.

`roadmaps.js` встроен в main.js скриптом `node scripts/bundle-roadmaps.cjs`: плагин не требует дополнительных runtime-модулей, включая мобильный Obsidian. После изменения исходника пересоберите main.js; `--check` проверяет актуальность встроенной копии. Для установки обновляются обычные main.js, styles.css и manifest.json.

## Проверки

```sh
node scripts/bundle-roadmaps.cjs --check
node --check main.js
node --check roadmaps.js
node tests/roadmaps.test.cjs
node tests/export.test.cjs
node tests/required-habits.test.cjs
git diff --check
```

Проверены последовательность трёх уровней, границы активации в один день, абсолютные значения, прирост, AND/OR, стрики, верхние пределы, пересчёт правок/удалений, восстановление, неизменность истории, регистрация новой метрики, защита редактора, отсутствие двойного зачёта, ошибки чтения/записи, параллельное подтверждение, интерфейс и запуск плагина с встроенным модулем. DOM-проверки используют контракт Obsidian; интерактивная проверка в реальном Obsidian не выполнялась.

Не добавлены отсутствующие в проекте банковские счета, дозировки/схемы приёма, XP навыков или новые системы фиксации времени событий. Вещества учитываются максимум как отмеченные календарные дни; следуйте существующей назначенной схеме.
